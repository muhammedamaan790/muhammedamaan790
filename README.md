## About

I am a software engineer and Computer Science student specialising in Cyber Security at VIT Chennai. I build AI systems that have to be right, not just plausible, and safe to trust. My work sits where machine learning meets product engineering: calibrated models, autonomous agents and real-time voice pipelines, shipped as full-stack applications with tests, deployment and an audit trail.

A common thread runs through everything I build. **The system shows its evidence.** My coronary review tool explains every prediction with exact SHAP contributions. My data investigator computes its confidence from the evidence it gathered, not from the model's claim about itself. My hotel voice agent answers prices and policies from a database, never from a language model, and refuses to speak a stale answer after the caller interrupts.

- **Software engineering.** Typed APIs, deterministic routing, reproducible builds, containerised deployment and large automated test suites.
- **AI / ML.** Gradient-boosted models with calibration and SHAP, LLM agents with tool use, speech-to-text and text-to-speech pipelines.
- **Full stack.** FastAPI and Python services behind React, TypeScript and Three.js interfaces, packaged with Docker and nginx.
- **Cyber security.** CTF challenges and writeups, plus security built into every project: hashed credentials, least-privilege data access, integrity checks and guardrails that keep LLMs away from facts they must not invent.
- **Product mindset.** Each project starts from a real workflow (a clinician's case review, a marketer's budget decision, a hotel guest's phone call) and ends with something a user can run.

**Open to:** Software engineering, AI/ML and cyber security internships and full-time roles · AI product engineering · Hackathon and open-source collaborations

## Featured Projects

<details>
<summary><b>NOVARION</b> · 3D coronary case review with explainable CAD and stenosis prediction</summary>

<br/>

A case-review system for the Multimodal AI Hackathon 2026, Track A (Cardiovascular Risk Visualization & Prediction). It predicts overall coronary artery disease and LAD, LCX and RCA stenosis, then colours each vessel of an interactive 3D heart by its calibrated probability.

| | |
| :--- | :--- |
| **Stack** | React 19 · TypeScript · Three.js / React Three Fiber · Tailwind · Recharts · FastAPI · XGBoost · scikit-learn · SHAP · Docker · nginx |
| **Scale** | 303 patients of the Extension of Z-Alizadeh Sani dataset (UCI #411); four prediction targets per case |
| **Performance** | About one second per prediction on the hosted model; Docker stack ready in about 15 seconds |
| **Security** | scrypt-hashed accounts loaded from secrets, never the repository; hash-verified Review Snapshots |
| **Impact** | Turns a tabular risk score into a guided review: case, quality gate, 3D review, clinician note, verified snapshot, history |
| **Repository** | [github.com/muhammedamaan790/Novarion](https://github.com/muhammedamaan790/Novarion) · [Live demo](https://novarion.onrender.com) |

Every prediction is explained with exact SHAP contributions beside the patient's measurements. A governed learning loop lets verified outcomes reach a model update only through a validation gate and human approval. The model bundle is versioned and pinned, and the full pipeline can be reproduced from the repository. Built for decision support and education, not diagnosis.

</details>

<details>
<summary><b>AETHER</b> · Multilingual hotel voice agent where interrupting is safe</summary>

<br/>

A telephone voice agent for hotels in English, Hindi and Spanish. Hotel facts come from a database through deterministic tools, and an abandoned answer is never spoken after the caller interrupts.

| | |
| :--- | :--- |
| **Stack** | Python 3.12 · LiveKit Agents & SIP · faster-whisper · SQLite · Gemini · Rime TTS |
| **Scale** | 33 deterministic tools · 3 languages · 1,994 automated tests |
| **Performance** | 1,262 ms median turn on a real phone line · 0.90 ms deterministic answer |
| **Security** | Prices and policies are never generated by the LLM; five generation-fencing checkpoints stop stale output |
| **Impact** | 0 stale outputs spoken in 112 interruption runs · 93/93 multilingual routes correct |
| **Repository** | [github.com/muhammedamaan790/AETHER-VOICE-AGENT](https://github.com/muhammedamaan790/AETHER-VOICE-AGENT) |

The core invariant is that a stale result must never become spoken output. On a phone, audio cannot be un-spoken, so instead of racing to cancel an abandoned generation, AETHER fences it at five checkpoints and refuses to speak it. A router sends each sentence to one of 33 SQLite-backed tools whose rows are spoken through per-language templates, and only unmatched questions reach Gemini.

</details>

<details>
<summary><b>Autonomous Enterprise Intelligence (AEI)</b> · An AI data investigator built on Exasol Personal</summary>

<br/>

Given a business question, AEI plans an investigation, runs a query, inspects the result as evidence and decides for itself whether that evidence is enough before it answers.

| | |
| :--- | :--- |
| **Stack** | Python · FastAPI · React 18 · TypeScript · Vite · Tailwind · Exasol Personal · DuckDB · pandas |
| **Scale** | Live Exasol database plus uploaded CSV, XLSX, XLS and JSON files, separately or together |
| **Performance** | Deterministic, non-LLM source routing; in-memory DuckDB execution for file investigations |
| **Security** | Session-based authentication; application-level SQL table allowlist for the restricted user role |
| **Impact** | Confidence computed by the application from gathered evidence, with table and join-path attribution |
| **Repository** | [github.com/muhammedamaan790/autonomous-enterprise-intelligence](https://github.com/muhammedamaan790/autonomous-enterprise-intelligence) |

Single-shot text-to-SQL reports the same confidence whether its first query was right or wrong. AEI runs the investigation as a loop instead: it plans steps, examines each result, issues more queries when the evidence is thin, and keeps a persistent investigation history with opt-in conversational continuation. Built by Team COLD with Aditya Tiwari and Swayam Biswas.

</details>

<details>
<summary><b>ADAPT</b> · D2C advertising intelligence and budget decision engine</summary>

<br/>

ADAPT combines campaign performance, SKU economics and inventory to recommend where the next rupee of ad spend should go. Each decision carries its evidence, forecast, policy checks and execution history. Built for DataQuest 3.0.

| | |
| :--- | :--- |
| **Stack** | Python decision engine · TypeScript frontend · CSS · GitHub Pages |
| **Scale** | Ads, orders, sessions, inventory and SKU economics reconciled into canonical records |
| **Performance** | Matured outcomes measured against a frozen forecast counterfactual |
| **Security** | Channel policy checks, decision-identity and dependency checks, guardrails and read-back verification on every budget change |
| **Impact** | Catches strong ROAS that hides a weak margin or a product about to run out of stock |
| **Repository** | [github.com/muhammedamaan790/ADAPT](https://github.com/muhammedamaan790/ADAPT) · [Frontend demo](https://muhammedamaan790.github.io/ADAPT/) |

ADAPT runs an observe, diagnose, decide, act and learn loop. It separates real efficiency changes from tracking problems, estimates response curves and inventory exposure, then allocates budget against contribution, risk and guardrails. After a change goes out, it compares the forecast with what actually happened and updates its optimism correction.

</details>
